# 시연 영상 작업계획서

열린영수증의 5분 이내 시연 영상을 만드는 계획과 대본입니다. 완성본 길이는 3분 7초입니다.

## 목표

- 등록자, 승인자, 후원자가 차례로 쓰는 실제 화면을 처음부터 끝까지 한 번에 보여 준다.
- 에이전트가 무엇을 하고 사람이 무엇을 결정하는지가 화면과 자막에서 드러나게 한다.
- Liner Model API와 Liner Search API가 어디에 쓰이는지 말한다.
- 5분을 넘지 않는다.

## 만드는 순서

1. **대본**: `script.json`에 장면마다 누구의 화면인지와 문장을 적는다.
2. **내레이션**: `node video/tts.mjs`. 문장마다 음성 파일을 만들고 길이를 잰다(`raw/durations.json`).
3. **녹화**: `RECORD_VIDEO=1 BASE_URL=https://open-receipt-six.vercel.app npx playwright test e2e/video-record.spec.ts`. 대본 순서대로 실제 앱을 조작하며 세 기기 화면을 녹화한다. 장면마다 내레이션이 끝날 때까지 화면을 붙잡아 두고, 장면의 시작과 끝 시각을 `raw/timeline.json`에 적는다. 실제 Liner를 부르므로 크레딧을 쓰고 5분쯤 걸린다.
4. **변환**: 녹화본(webm)을 편집용 MP4로 바꿔 `public/clips/`에 둔다.
   `ffmpeg -i raw/submitter.webm -vf "crop=450:900:0:0,fps=30,scale=496:992:flags=lanczos" -c:v libx264 -crf 16 -pix_fmt yuv420p -an public/clips/submitter.mp4` (approver, sponsor도 같은 방법)
5. **인코딩**: `node video/build.mjs`. 대본, 내레이션 길이, 장면 시각을 합쳐 편집 목록(`raw/edl.json`)을 만들고 Remotion으로 `out/open-receipt-demo.mp4`를 만든다. 5분을 넘으면 멈춘다.

처음 한 번은 `cd video && npm install`이 필요합니다. 브라우저는 새로 내려받지 않고 Playwright가 설치해 둔 것을 씁니다.

## 고칠 때

- **문장만 고칠 때**: `script.json`을 고치고 2번과 5번을 다시 한다. 문장이 길어지면 화면이 먼저 끝날 수 있으니 3번도 다시 하는 편이 안전하다.
- **화면 순서를 바꿀 때**: `e2e/video-record.spec.ts`의 장면을 고치고 3번부터 다시 한다.
- **사람 목소리로 바꿀 때**: `public/audio/`의 장면별 파일(`r1.wav` 등)을 같은 이름의 녹음으로 바꾸고, 길이가 달라졌으면 `raw/durations.json`을 고친 뒤 3번부터 다시 한다.
- **캐릭터를 바꿀 때**: `src/Framey.tsx`만 바꾸면 된다.

## 알아 둘 점

- 실제 모델의 답은 녹화할 때마다 조금씩 다르다. 질문의 개수, 항목 이름, 브리핑 문장이 달라질 수 있어 녹화 스크립트가 나온 질문에만 답하도록 되어 있다.
- 내레이션은 기계 음성이라 억양이 어색한 곳이 있다.
- 휴대폰 화면은 450×900으로 녹화해 조금 키운 것이라, 작은 글자는 원래 화면보다 덜 선명하다.
- Remotion은 개인과 소규모 팀에는 무료지만 회사 규모에 따라 유료 라이선스가 필요하다. 쓰기 전에 조건을 확인한다.
