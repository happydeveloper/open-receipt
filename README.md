# 열린영수증

영수증 한 장을 올리면 AI 에이전트가 지출 기록을 채우고, 모르는 것만 되묻고, 관련 공개 지침을 찾아 "증빙 묶음"을 완성합니다. 월말에는 마감 점검 에이전트가 전체 기록을 훑어 보완 요청 문안과 브리핑을 준비하고, 사업별 결산보고서 초안을 만듭니다. 라이너 .EXE-THON 출품작입니다.

- 소개 페이지: https://open-receipt-six.vercel.app (취지, 실제 화면으로 보는 사용법, 출시 알림 신청)
- 앱: https://open-receipt-six.vercel.app/app
- 시연 영상: https://youtu.be/BgRsjSCLiHw
- 모델과 검색: Liner Model API(도구 호출 + 이미지 입력), Liner Search API
- 에이전트와 화면 사이의 통신: [AG-UI 프로토콜](https://docs.ag-ui.com/) 1.0
- 사용 안내: https://open-receipt-six.vercel.app/guide (등록자·승인자·후원자가 화면을 보고 따라 하는 방법)
- 개발자 안내: https://open-receipt-six.vercel.app/developers (다른 서비스에서 에이전트를 부르는 방법, 예제, 직접 실행)
- 화면: Meta의 오픈소스 디자인 시스템 [Astryx](https://github.com/meta/astryx) (`@astryxdesign/core`, neutral 테마)

## 실행 방법

Node.js 22 이상이 필요합니다.

```bash
git clone https://github.com/happydeveloper/open-receipt.git
cd open-receipt
npm install
cp .env.example .env.local   # LINER_API_KEY 입력 (https://platform.liner.com/keys)
npm run dev                  # http://localhost:3000
```

브라우저에서 http://localhost:3000 을 열면 소개 페이지가, http://localhost:3000/app 을 열면 앱이 나옵니다. 앱에서 **데모 데이터 불러오기**를 누르면 가상 단체와 가상 영수증으로 바로 써 볼 수 있습니다.

API 키는 서버(`lib/liner.ts`)에서만 읽습니다. 키가 없어도 앱은 열리고 직접 입력으로 쓸 수 있습니다. 설치 없이 써 보려면 배포본(https://open-receipt-six.vercel.app/app)을 여세요.

| 환경 변수 | 필요 | 내용 |
| --- | --- | --- |
| `LINER_API_KEY` | 에이전트를 쓰려면 | Liner Platform API 키 |
| `LINER_MODEL` | 선택 | 모델 이름. 기본값 `liner-gpt-router` |
| `BLOB_READ_WRITE_TOKEN` | 배포 환경에서 단체 공간을 쓰려면 | Vercel Blob 저장소 토큰. Vercel에서 Blob 저장소를 연결하면 자동으로 들어갑니다. 로컬 개발에서는 없어도 되고 `.data/` 폴더에 저장합니다 |
| `NEXT_PUBLIC_SOURCE_URL` | 선택 | 소스 저장소 주소. 넣으면 소개 페이지에 "소스 코드 받기" 버튼이 나옵니다 |

### 직접 배포하기

Vercel에 올리는 경우: 저장소를 Vercel 프로젝트로 가져오고, 환경 변수에 `LINER_API_KEY`를 넣고, Storage에서 Blob 저장소(비공개)를 만들어 프로젝트에 연결합니다. 다른 곳에 올리려면 `lib/sync-store.ts`의 `SyncStore` 인터페이스를 그곳의 저장소로 구현하면 됩니다.

## Liner API를 사용한 기능

핵심 기능인 세 에이전트(지출, 마감 점검, 묶음)가 Liner Model API와 Liner Search API로 동작합니다. 호출은 모두 서버의 `lib/liner.ts`를 거칩니다.

| 기능 | 쓰는 API | 하는 일 | 코드 |
| --- | --- | --- | --- |
| 영수증 읽기 | Model API (이미지 입력) | 가린 영수증 사진에서 일자, 금액, 가맹점, 항목, 결제 방식을 읽어 기록을 채웁니다 | `lib/agent.ts`의 `update_record` |
| 지출 에이전트 | Model API (도구 호출) | 모델이 도구 여섯 개 가운데 다음에 쓸 것을 스스로 골라 가며 증빙 묶음을 완성합니다. 지난 기록을 참고해 사업과 예산 항목을 맞추고, 빠진 것을 점검하고, 알 수 없는 것만 사용자에게 묻습니다 | `lib/agent.ts`의 `runExpenseAgent` |
| 공개 지침 검색 | Search API | 지출 종류와 결제 방식에 맞는 공개 정산·증빙 지침을 검색합니다. 결과가 맞지 않으면 에이전트가 검색어를 바꿔 다시 찾습니다 (한 번 실행에 3번까지) | `lib/agent.ts`의 `search_guidelines` |
| 확인할 자료 | Model API + Search API | 검색 결과를 읽고 이 지출에서 챙길 자료를 출처 링크와 함께 정리합니다. 검색 결과에 실제로 있는 주소가 달린 항목만 남깁니다 | `lib/agent.ts`의 `validChecklist` |
| 기록 요약 | Model API | 지출 한 건을 결산보고서에 들어갈 두 문장 이내로 요약합니다 | `lib/agent.ts`의 `finish` |
| 같은 거래 묶기 | Model API (도구 호출) | 카드영수증, 거래명세서, 주문 화면 캡처처럼 한 번 쓴 돈의 서류가 따로 올라오면, 날짜·금액·가맹점·서류 종류를 견줘 같은 거래를 추론하고 한 건으로 합치자고 제안합니다. 가맹점 표기나 날짜가 조금 달라도 찾습니다. 합치는 것은 사람이 누를 때만 됩니다 | `lib/agent.ts`의 `runGroupAgent`, `lib/group.ts` |
| 여러 장 올리기 | Model API, Search API | 영수증 30장까지를 두 장씩 지출 에이전트에 맡겨 초안으로 정리합니다 | `app/app/page.tsx`의 `runBulk` |
| 마감 점검 에이전트 | Model API (도구 호출), Search API | 사업의 기록을 모두 살펴 보완이 필요한 건마다 담당자에게 보낼 요청 문안을 쓰고 브리핑을 만듭니다 | `lib/agent.ts`의 `runCloseAgent` |

호출 방식:

- **Model API**: `POST https://platform.liner.com/api/v1/chat/completions`. 기본 모델은 `liner-gpt-router`이고, 도구 호출을 필수로 겁니다(`tool_choice: "required"`). 영수증 사진은 메시지의 이미지 파트(data URI)로 보냅니다.
- **Search API**: `POST https://platform.liner.com/api/v1/tools/search/web`. 한 번에 8건을 받습니다.
- **키 보호**: `LINER_API_KEY`는 서버에서만 읽고 브라우저로 나가지 않습니다. 테스트가 이를 확인합니다(`tests/proxy.test.ts`).
- **실패 대비**: 429와 5xx는 한 번 다시 시도하고, 30초 안에 응답이 없으면 끊습니다. 어떤 오류든 사용자는 직접 입력으로 계속할 수 있습니다.
- **보내는 것**: 가린 사진, 숫자 패턴을 가린 메모, 기록 값만 보냅니다. 원본 사진은 보내지 않습니다.

에이전트가 쓰는 도구 전체와 안전장치는 아래 "에이전트가 하는 일"에 있습니다.

## 사용법

### 0. 처음 시작하기

처음 열면 서비스 소개와 시작 화면이 나옵니다.

- **우리 단체로 시작하기**: 단체 이름, 내 이름, 승인하는 사람, 첫 사업·행사 이름, 지원기관(선택)을 넣고 **시작하기**를 누릅니다.
- **데모 데이터 불러오기**: 가상 단체와 가상 지출 2건으로 바로 둘러봅니다.

이름과 사업은 나중에 **설정**에서 바꾸거나 추가할 수 있습니다. 휴대폰에서는 브라우저 메뉴의 "홈 화면에 추가"로 앱처럼 설치할 수 있습니다.

### 0-1. 여러 사람이 각자 기기에서 함께 쓰기 (단체 공간)

총무와 승인자가 서로 다른 기기를 쓴다면 단체 공간을 만듭니다.

1. 총무: **설정 → 단체 공간 만들기** → **초대 링크 복사**로 링크를 단체 사람에게 보냅니다.
2. 받은 사람: 링크를 열고 내 이름과 역할(기록을 올리는 사람 / 승인하는 사람)을 고른 뒤 **참여하기**를 누릅니다.
3. 이후에는 기록을 올리거나 승인할 때마다 자동으로 맞춰집니다. 목록 화면의 **동기화**로 바로 맞출 수도 있습니다.

승인하는 사람으로 참여하면 승인할 때 그 사람의 이름이 승인자로 기록됩니다. 한쪽에서 지운 기록은 다른 기기에서도 사라지고, 같은 기록을 양쪽에서 고쳤으면 나중에 고친 쪽이 남습니다.

단체 공간에서는 **승인하는 사람** 역할만 승인할 수 있고, 자기가 올린 지출은 다른 승인자가 승인합니다. 승인한 일과, 승인된 기록을 고쳐 승인이 풀린 일은 기록 상세의 **변경 이력**에 남습니다. 혼자 쓰는 기기(단체 공간 없음)에서는 한 기기에서 등록과 승인을 함께 합니다. 로그인이 없으므로 이 제한은 화면 수준의 규칙이며, 초대 링크를 가진 사람이 기기를 조작하면 우회할 수 있습니다.

여러 사람이 같은 영수증을 올리는 경우를 위해, 날짜와 금액이 같고 가맹점이 같거나 비어 있는 기록이 있으면 확정 전에 **같은 영수증일 수 있습니다**라고 알립니다. 목록과 검토 화면에는 "중복 확인" 표시가 남고, 여러 장 올리기의 한꺼번에 확정은 이런 초안을 건너뜁니다. 경고일 뿐 저장을 막지는 않습니다.

기록과 영수증 사진은 기기에서 암호화(AES-GCM)한 뒤 서버에 올립니다. 열쇠는 초대 링크에만 들어 있어 서버는 내용을 읽을 수 없습니다. 대신 초대 링크를 가진 사람은 누구나 참여해 보고 고칠 수 있으니 단체 사람에게만 보내세요. 링크를 잃어버리면 그 단체 공간에는 새 기기를 추가할 수 없습니다.

단체 공간을 쓰지 않는다면 기록은 그 브라우저에만 저장됩니다. 보관하거나 옮기려면 설정의 **백업 내보내기 / 백업 가져오기**를 씁니다.

### 1-0. 영수증 여러 장 한꺼번에 올리기 (행사 뒤 정산)

행사가 끝나고 모아 둔 영수증은 **영수증 여러 장 올리기**로 한꺼번에 올립니다.

1. 목록 화면에서 정산할 사업을 고르고 **영수증 여러 장 올리기**를 누릅니다.
2. **사진 선택 (여러 장)**으로 사진을 고릅니다(한 번에 30장까지). 이름이나 카드번호 전체가 보이는 사진은 **가리기**로 가립니다.
3. 공통 메모를 적고(선택) **N장 에이전트에게 맡기기**를 누릅니다. 에이전트가 두 장씩 읽어 그 사업의 기록 초안으로 정리합니다. 이때는 묻지 않고 끝까지 진행합니다.
4. 목록으로 돌아와 **초안 N건 한꺼번에 확정**을 누르면 필수 정보가 다 채워진 초안이 승인 대기로 넘어갑니다. 금액을 읽지 못한 것처럼 빠진 정보가 있는 초안은 검토 목록에서 **수정**으로 채웁니다.

### 1. 지출 한 건 기록하기 (총무·재정 담당)

1. **+ 지출 추가** → 영수증 사진을 선택합니다(데모에서는 **가상 영수증 사용**). 메모에 "간식 샀어요"처럼 한 줄을 적어도 됩니다.
2. **다음: 가릴 부분 확인**에서 이름·카드번호 위를 끌어서 가립니다. AI에는 가린 사진만 전송됩니다. 원본은 기기에 따로 보관되어 등록자와 승인자만 볼 수 있습니다.
3. **에이전트에게 맡기기**를 누르면 에이전트가 한 일이 순서대로 표시됩니다. 예: 기록을 채움 → 지난 기록 확인 → 증빙 묶음 점검 → 질문.
4. 에이전트가 스스로 알 수 없는 것(목적, 결제자, 환급 여부 등)만 묻습니다. 답하고 **답하고 계속**을 누릅니다.
5. 에이전트가 공개 지침을 검색해 "확인할 자료"를 출처 링크와 함께 정리합니다. 내용을 보고 **내용 확정**을 누르면 "승인 대기"로 저장됩니다. 고칠 것이 있으면 **수정**에서 직접 바꿉니다.

영수증이 없으면 1번에서 **영수증이 없어요**를 눌러 대체 자료 종류와 사유를 적습니다. 에이전트가 실패하거나 키·크레딧이 없으면 **직접 입력으로 계속**으로 끝까지 기록할 수 있습니다.

저장한 기록은 목록에서 눌러 상세를 보고 **수정**하거나 **삭제**할 수 있습니다. 승인이 끝난 기록을 수정하면 다시 승인 대기로 돌아갑니다.

### 2. 검토와 마감 (대표·승인자)

1. **검토 목록**에서 보완이 필요한 건과 다음 행동을 확인하고, 승인 대기 건은 **승인**합니다.
2. **마감 점검 맡기기**를 누르면 마감 점검 에이전트가 기록을 모두 살펴 브리핑과 건별 요청 문안 초안을 만듭니다. 문안은 **문안 복사**로 가져가 직접 보냅니다. 에이전트는 메시지를 보내지 않습니다.
3. **결산보고서 보기**에서 요약, 예산 항목별·결제 방식별 집행, 지출 내역, 확인할 항목, 환급 대상, 참고한 공개 지침을 확인하고 **CSV 내려받기**, **보고서 내려받기**, **인쇄**를 씁니다.

### 3. 역할별로 보이는 것

| 역할 | 들어오는 방법 | 볼 수 있는 것 | 할 수 있는 것 |
| --- | --- | --- | --- |
| 등록자 (총무·재정 담당) | 앱에서 시작, 또는 초대 링크로 참여 | 기록 전체, 결산보고서, 가린 영수증, 원본 영수증 | 기록 올리기·수정·삭제, 보고서 공유 |
| 승인자 (대표) | 초대 링크로 "승인하는 사람" 참여 | 등록자와 같음 | 승인(자기 이름으로 기록), 수정 |
| 후원자 | 후원자용 보기 링크 | 결산보고서, 가린 영수증 | 보기와 인쇄만. 원본·이름(기본값)·수정 기능 없음 |

- 결산보고서 화면의 **8. 영수증**에서 건별 영수증을 봅니다. 등록자와 승인자는 **가린 사진 / 원본**을 바꿔 볼 수 있습니다.
- 후원자용 보기는 **설정 → 단체 공간 → 후원자용 보기 → 열림**으로 켜고, 나오는 링크를 후원자에게 보냅니다. 이름 표시 여부를 고를 수 있고, **닫힘**으로 바꾸면 링크로 더 볼 수 없습니다. 기록이 바뀌면 후원자가 보는 보고서도 따라 바뀝니다.
- 후원자 링크의 열쇠는 구성원 열쇠에서 한 방향으로 만든 것이라, 이 열쇠로는 원본 영수증과 기록을 열 수 없고 아무것도 고칠 수 없습니다.
- 원본 영수증은 AI에 보내지 않습니다. 올린 기기의 저장소(IndexedDB)에 두고, 단체 공간을 쓰면 암호화해 등록자와 승인자의 기기에만 전달합니다.

### 4. 결산보고서를 링크 하나로 보내기 (사진 없이)

결산보고서 화면 아래 **보고서 공유**에서 링크를 만듭니다.

1. 공유 범위를 고릅니다: **지출 내역 포함** 또는 **요약만**(합계와 항목별·결제 방식별 집행만).
2. 이름 표시를 고릅니다: 기본값은 **이름 가림**입니다. 결제자 이름과 요약 문장이 빠집니다.
3. **공유 링크 만들기** → **링크 복사** 또는 **공유하기**(휴대폰의 공유 메뉴)로 보냅니다.

단체 공간 없이도 쓸 수 있는 간단한 방법입니다. 영수증 사진까지 보여 주려면 위의 후원자용 보기를 쓰세요.

받는 사람은 로그인이나 설치 없이 링크만 열면 읽기 전용 보고서를 봅니다. 보고서 내용은 압축되어 링크의 `#` 뒤에 담기며 서버에는 저장되지 않습니다. 따라서 링크를 가진 사람은 누구나 볼 수 있고, 한번 보낸 링크는 회수할 수 없으며, 이후에 기록을 고쳐도 이미 보낸 링크의 내용은 바뀌지 않습니다. 영수증 사진은 포함되지 않습니다.

## 에이전트가 하는 일

에이전트는 정해진 순서를 따르지 않고, 목표를 받아 도구를 스스로 골라 가며 끝날 때까지 반복합니다 (`lib/agent.ts`).

| 에이전트 | 목표 | 쓸 수 있는 도구 |
| --- | --- | --- |
| 지출 에이전트 | 지출 한 건의 증빙 묶음 완성 | `update_record` 기록 채우기, `lookup_history` 지난 기록 조회, `check_bundle` 묶음 점검, `ask_user` 사용자에게 묻기, `search_guidelines` 공개 지침 검색(Liner Search), `finish` 마무리 |
| 마감 점검 에이전트 | 제출 전 보완 요청과 브리핑 준비 | `list_records`, `inspect_record`, `search_guidelines`, `draft_request` 요청 문안 초안, `finish` |

안전장치:

- 승인·확정·송금·메시지 발송 도구는 없습니다. 상태는 사람의 확정·승인 클릭으로만 바뀝니다 (`lib/status.ts`).
- 사람이 직접 넣은 값은 에이전트가 덮어쓰지 못합니다.
- "확인할 자료"는 검색 결과에 실제로 있는 URL이 달린 항목만 남깁니다.
- "적법/위반" 같은 판정 표현은 걸러 "확인이 필요합니다"로 바꿉니다 (`lib/guard.ts`).
- 한 번 실행에 모델 호출 10회, 검색 3회, 질문 2회까지만 허용합니다. 필수 정보가 빈 채로 끝내려 하면 한 번 돌려보냅니다.

## AG-UI 프로토콜 연동

화면과 에이전트는 AG-UI 1.0 규격으로 통신합니다. 서버는 손으로 구현했고(`lib/agui-server.ts`), 화면은 공식 클라이언트 `@ag-ui/client`의 `HttpAgent`를 씁니다(`app/app/page.tsx`). 그래서 AG-UI를 지원하는 다른 프런트엔드에서도 이 에이전트를 그대로 부를 수 있습니다.

엔드포인트 (POST, 본문은 `RunAgentInput` JSON, 응답은 `text/event-stream`):

| 주소 | 에이전트 | `state`에 넣는 것 |
| --- | --- | --- |
| `/api/agent/expense` | 지출 에이전트 | `record`, `locked`, `evidence`, `history`. 단체 이름·지원기관·현재 사업은 `context`로 전달 |
| `/api/agent/close` | 마감 점검 에이전트 | `project`, `records` |
| `/api/agent/group` | 묶음 에이전트 | `documents` (서류별 날짜, 금액, 가맹점, 항목, 결제 방식, 서류 종류). 결과는 `groups` |

한 번의 실행에서 오가는 이벤트:

```
RUN_STARTED (protocolVersion "1.0")
STATE_SNAPSHOT                      기준 상태
  TOOL_CALL_START / ARGS / END      에이전트가 고른 도구
  TOOL_CALL_RESULT                  서버가 실행한 도구의 결과
  ACTIVITY_SNAPSHOT                 화면에 보여 줄 진행 단계 ("기록을 채웠습니다")
  STATE_DELTA                       기록 변경 (JSON Patch)
TEXT_MESSAGE_START / CONTENT / END  요약 또는 브리핑
RUN_FINISHED | RUN_ERROR
```

사용자에게 묻기는 AG-UI의 프런트엔드 도구 방식으로 처리합니다.

1. 화면이 `tools`에 `ask_user` 도구를 실어 보냅니다.
2. 에이전트가 `ask_user`를 호출하면 서버는 답하지 않고 `RUN_FINISHED`의 `outcome.pendingToolCallIds`에 그 호출 id를 담아 실행을 끝냅니다.
3. 화면이 질문 카드를 띄우고, 답을 `role: "tool"` 메시지로 `messages`에 붙여 다음 실행을 시작합니다.

서버는 실행 사이에 아무것도 저장하지 않습니다. 대화는 `messages`에, 기록과 검색 출처는 `state`에 실려 옵니다. 영수증 이미지는 user 메시지의 `image` 파트(base64)로 보냅니다. 실행 전 오류(형식 오류, 허용되지 않는 이미지)는 HTTP 400으로, 실행 중 오류는 스트림 안의 `RUN_ERROR`로 알립니다.

다른 출처의 브라우저에서도 부를 수 있도록 세 엔드포인트의 CORS를 열어 두었습니다. `HttpAgent` 예제, 상태 구조, 질문 받고 답하는 방법은 앱의 [개발자 안내](https://open-receipt-six.vercel.app/developers) 페이지(`app/developers/page.tsx`)에 있습니다. 인증이 없는 시연용 엔드포인트이므로 실서비스에 붙이려면 자신의 Liner 키로 직접 배포하세요. 한 주소에서 10분에 80번, 하루 400번을 넘거나 전체 호출이 하루 3,000번을 넘으면 `429`와 `Retry-After`로 거절합니다(`lib/rate-limit.ts`). 횟수를 서버 인스턴스 메모리에 두는 안전장치여서 정확한 상한은 아닙니다.

직접 호출 예:

```bash
curl -N https://open-receipt-six.vercel.app/api/agent/expense \
  -H "Content-Type: application/json" -H "Accept: text/event-stream" \
  -d '{"threadId":"t1","runId":"r1","messages":[{"id":"u1","role":"user","content":"11월 18일 워크숍 다과 26,400원 개인 카드로 결제"}],"tools":[],"context":[],"state":{"record":{},"evidence":{"kind":"none"}}}'
```

## 단체 공간 동기화 구조

| 구성 | 위치 | 하는 일 |
| --- | --- | --- |
| 암호화 | `lib/sync-crypto.ts` | 단체 공간 주소·열쇠 생성, AES-GCM 암복호화, 쓰기 증표 |
| 합치기 | `lib/sync-merge.ts` | 기록별 최근 변경 우선, 삭제 기록(tombstone), 이미지 분리 |
| 동기화 | `lib/sync-client.ts` | 받기 → 합치기 → 올리기. 다른 기기가 먼저 올렸으면 다시 받아 재시도 |
| 서버 | `lib/sync-store.ts`, `app/api/sync/` | 암호문 보관, 버전 충돌 감지(409), 열쇠 가진 사람만 쓰기 |
| 원본 보관 | `lib/originals.ts` | 원본 영수증을 기기의 IndexedDB에 보관 |
| 후원자용 보기 | `lib/sponsor-view.ts`, `app/v/page.tsx` | 결산보고서와 가린 영수증을 후원자 열쇠로 암호화해 게시, 읽기 전용 화면 |

서버는 단체 공간 주소와 암호문, 쓰기 증표의 해시만 압니다.

## 서명 원장

기록이 바뀌지 않았음을 여러 기기가 서로 확인하기 위한 구조입니다(`lib/ledger.ts`). 블록체인의 해시 사슬과 전자서명을 쓰고, 채굴·합의 알고리즘·코인은 없습니다.

1. **기기 열쇠**: 기기마다 ECDSA P-256 열쇠 쌍을 만듭니다. 열쇠 id는 공개 열쇠의 해시이고, 비밀 열쇠는 그 기기의 브라우저에만 있습니다.
2. **서명한 줄**: 기록을 올리거나 고치거나 승인하거나 지우면 그 기기의 원장에 한 줄을 덧붙입니다. 줄에는 기록 내용의 해시, 앞줄의 해시, 그때 밝힌 이름과 역할이 들어가고 기기 열쇠로 서명합니다.
3. **기기별 원장**: 원장이 기기마다 따로 있어서 여러 기기가 동시에 써도 충돌하지 않습니다.
4. **서로 가진 사본**: 단체 공간 문서에 모든 원장이 함께 실립니다. 동기화할 때 받은 원장의 서명과 사슬을 검증하고, 실패한 원장은 받지 않습니다. 같은 기기의 원장은 한쪽이 다른 쪽의 앞부분일 때만 긴 쪽을 받으므로, 누가 서버 사본을 잘라 내도 다른 기기의 사본이 되살립니다.
5. **승인 검증**: 승인자 역할을 밝힌 기기가, 그 내용을 올린 기기와 다른 열쇠로 서명한 승인만 인정합니다. 아니면 기록 상세에 "승인 서명을 확인할 수 없습니다"가 뜹니다.
6. **지문**: 결산보고서, 공유 링크, 후원자용 보기에 "보고서 지문"(그 사업 기록 전체의 해시)과 "원장 지문"이 함께 나갑니다. 후원자용 보기는 지난번에 본 지문을 브라우저에 기억해 두고, 달라졌으면 알려 줍니다.

한계: 이름과 역할은 각 기기가 스스로 밝힌 값이라, 한 사람이 기기 두 대로 등록자와 승인자를 겸하는 것은 막지 못합니다(설정의 기기 목록에서 드러나기는 합니다). 영수증 사진은 해시만 줄에 남기고 검증 화면은 아직 없습니다. 구성원 전원이 원장을 통째로 새로 만드는 것은 외부에 준 지문과 견줘야만 드러납니다. 원장은 기록이 바뀌지 않았음을 보여 줄 뿐, 내용이 사실인지는 증명하지 않습니다.

## 데이터와 한계

- 모든 인물·단체·거래·영수증(`public/demo-receipt.png`)은 시연용 가상 데이터입니다.
- 로그인과 계정이 없습니다. 기록은 각 기기의 브라우저에 저장되고, 단체 공간을 만들면 암호화되어 기기 사이에 맞춰집니다. 승인자만 승인한다는 규칙은 화면 수준이어서, 초대 링크를 가진 사람은 모든 기록을 읽고 고칠 수 있습니다.
- 단체 공간의 서버 저장소는 Vercel Blob입니다. 배포 환경에 Blob 저장소가 연결되어 있어야 동작하고(`BLOB_READ_WRITE_TOKEN`), 로컬 개발에서는 `.data/` 폴더에 저장합니다.
- 공유 링크는 접근 제한이나 만료가 없습니다. 민감한 내용이면 "요약만"과 "이름 가림"으로 공유하세요.
- 이미지 가림은 사용자가 그린 상자로 처리합니다. 이미지 속 개인정보 자동 탐지는 없습니다. 메모의 카드번호·전화번호·주민번호 패턴은 자동으로 가립니다.
- 검색된 지침이 해당 조직에 실제로 적용되는지는 판단하지 않습니다.
