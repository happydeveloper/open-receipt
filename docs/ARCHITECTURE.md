# 구조 안내

코드를 처음 읽는 사람을 위한 지도입니다. 무엇이 어디에 있고, 자료가 어떤 길로 흐르며, 어떤 약속을 지키고 있는지 적었습니다. 사용법은 [USAGE.md](USAGE.md)에, 에이전트와 동기화가 동작하는 방식은 [INTERNALS.md](INTERNALS.md)에 있습니다.

## 한눈에 보기

```
브라우저 (기기마다 하나)                         서버 (Next.js, Vercel)                 바깥
┌──────────────────────────────────┐      ┌────────────────────────────┐      ┌──────────────┐
│ app/app/page.tsx  앱 화면         │ AG-UI│ app/api/agent/*            │ HTTPS│ Liner        │
│   └ lib/status, flow, report ...  │─────▶│   └ lib/agui-server.ts     │─────▶│  Model API   │
│                                   │ SSE  │       └ lib/agent.ts       │      │  Search API  │
│ localStorage  기록·설정·원장       │◀─────│           └ lib/liner.ts   │      └──────────────┘
│ IndexedDB     가린 사진·원본 사진  │      │                            │
│                                   │ 암호문│ app/api/sync/*             │      ┌──────────────┐
│ lib/sync-client.ts  동기화        │◀────▶│   └ lib/sync-store.ts      │─────▶│ Vercel Blob  │
│ lib/sync-crypto.ts  암호화        │      │                            │      │ (암호문만)    │

└──────────────────────────────────┘      └────────────────────────────┘
```

기억할 것 세 가지:

1. **기록은 기기에 있습니다.** 서버에는 계정도 데이터베이스도 없습니다. 기록, 설정, 서명 원장은 브라우저의 localStorage에, 사진은 IndexedDB에 있습니다.
2. **서버는 두 가지 일만 합니다.** 에이전트를 돌려 Liner를 부르는 일(상태를 저장하지 않음)과, 단체 공간의 암호문을 맡아 두는 일(내용을 읽을 수 없음)입니다.
3. **규칙은 `lib/`에, 화면은 `app/`에 있습니다.** `lib/`의 모듈은 대부분 브라우저 없이 테스트할 수 있는 순수 함수이고, 화면은 그것을 불러 쓰기만 합니다.

## 지출 한 건이 지나는 길

영수증을 올려 승인되기까지입니다.

1. **사진과 가림** (`app/app/page.tsx`). 사진을 긴 변 1600px 이하로 줄이고, 사용자가 그린 상자를 검게 덮은 사본을 만듭니다(`lib/mask.ts`). 원본은 이 기기의 IndexedDB에만 둡니다.
2. **에이전트 실행**. 화면이 `@ag-ui/client`의 `HttpAgent`로 `/api/agent/expense`를 부릅니다. 가린 사진, 메모(숫자 패턴을 가린 것), 지금까지의 기록 값, 사람이 넣어 잠긴 필드 목록을 보냅니다.
3. **도구 반복** (`lib/agent.ts`의 `runLoop`). 모델이 도구를 고르면 서버가 실행하고 결과를 돌려주기를 되풀이합니다. 도구는 기록 채우기, 지난 기록 조회, 묶음 점검, 사용자에게 묻기, 공개 지침 검색, 마무리 여섯 가지입니다. 승인하거나 확정하는 도구는 없습니다.
4. **질문**. 모델이 `ask_user`를 부르면 서버는 답하지 않고 실행을 끝냅니다. 화면이 질문 카드를 띄우고, 답을 대화에 붙여 다음 실행을 시작합니다. 서버는 실행 사이에 아무것도 기억하지 않습니다.
5. **결과 반영** (`lib/flow.ts`의 `applyAgentRecord`). 돌아온 값을 기록에 넣되 사람이 넣은 값은 덮어쓰지 않고, AI가 채운 필드에는 "AI 초안" 표시를 붙입니다.
6. **확정** (`lib/status.ts`의 `confirmExpense`). 사람이 **내용 확정**을 누르면 상태가 "승인 대기"가 됩니다.
7. **저장** (`persist`). 바뀐 기록에 시각을 찍고, 기기에 저장하고, 이 기기의 원장에 서명한 줄을 덧붙입니다(`lib/ledger.ts`).
8. **동기화** (`lib/sync-client.ts`). 단체 공간에 들어가 있으면 서버의 문서를 받아 합치고, 암호화해 다시 올립니다.
9. **승인** (`approveExpense`). 승인자의 기기가 기록을 받아 승인하면, 그 기기의 원장에 승인 줄이 남고 다시 동기화됩니다.

코드를 고칠 때 깨뜨리면 안 되는 것들입니다. 각각 테스트가 지키고 있습니다.

| 약속 | 지키는 곳 | 테스트 |
| --- | --- | --- |
| 상태는 사람의 확정·승인으로만 바뀐다. 에이전트에는 그런 도구가 없다 | `lib/status.ts`, `lib/agent.ts` | `tests/core.test.ts` T-15 |

## 단체 공간

- **열쇠**: 단체 공간을 만들면 주소(id)와 AES-GCM 열쇠가 생기고, 둘 다 초대 링크에 들어갑니다. 서버에는 주소만 갑니다. 암호를 정해 만든 공간은 링크에 열쇠 대신 무작위 값이 들어가고, 열쇠는 그 값과 암호로 기기에서 만듭니다(PBKDF2-SHA256 31만 회, `lib/sync-crypto.ts`의 `lockedKey`). 쓰기 증표도 열쇠에서 나오므로 암호를 모르면 읽지도 쓰지도 못합니다. 암호는 서버로 가지 않고 기기에도 저장하지 않습니다.
- **쓰기 증표**: 열쇠에서 한 방향으로 만든 값입니다. 서버는 이 값의 해시만 보관하고, 같은 증표를 내는 요청만 쓰게 합니다.
- **후원자 열쇠**: 구성원 열쇠에서 한 방향으로 만듭니다. 후원자 열쇠에서 구성원 열쇠를 되찾을 수 없습니다.
- **문서**: 기록, 삭제 기록, 함께 쓰는 설정, 모든 기기의 원장을 한 문서로 암호화합니다. 서버는 버전마다 새 파일로 쓰고, 두 기기가 같은 버전을 쓰려 하면 한쪽에 409를 돌려줍니다. 409를 받은 기기는 다시 받아 합친 뒤 올립니다.
- **합치기**: 같은 기록은 칸 단위로 합칩니다(`mergeRecord`). 기록을 고칠 때 바뀐 칸마다 시각(`fieldAt`)을 찍어 두고, 합칠 때 더 최근에 바뀐 사본을 바탕으로 다른 사본이 더 나중에 고친 칸만 가져옵니다. 서로 다른 칸을 고쳤으면 둘 다 남고, 같은 칸이면 나중 것이 남습니다. 승인한 뒤 다른 기기에서 내용이 바뀌었으면 승인을 풉니다. 양쪽 수정이 섞인 기록은 합친 기기가 서명합니다. 확정된 기록을 고치면 무엇을 고쳤는지, 같은 칸이 덮였으면 무엇이 덮였는지를 기록의 이력에 남깁니다(`lib/history.ts`).

## 서명 원장

기기마다 ECDSA P-256 열쇠와 원장(줄의 목록)이 하나씩 있습니다. 줄 하나는 "어느 기기가, 어떤 이름과 역할로, 어느 기록을, 어떤 내용(해시)으로 올렸다·승인했다·지웠다"이고, 앞줄의 해시를 담아 사슬을 이룹니다.

- 원장이 기기마다 따로 있어서 합의 절차가 필요 없습니다. 합칠 때는 같은 기기의 두 사본 가운데 한쪽이 다른 쪽의 앞부분일 때만 긴 쪽을 받습니다(`mergeLedgers`).
- 기록 상세의 서명 표시는 지금 기록의 해시와 같은 줄이 원장에 있는지로 정합니다(`auditRecord`). 저장소의 값을 몰래 고치면 해시가 달라져 "서명한 기기가 없습니다"가 됩니다.
- 지문은 두 가지입니다. 보고서 지문은 그 사업 기록들의 해시, 원장 지문은 모든 원장 끝줄의 해시입니다.

원장은 기록이 서명된 뒤 바뀌지 않았음을 보여 줄 뿐입니다. 이름과 역할은 각 기기가 스스로 밝힌 값이고, 기록 내용이 사실인지는 증명하지 않습니다. 자세한 한계는 [INTERNALS.md](INTERNALS.md)의 "서명 원장"에 있습니다.

## 고칠 때 볼 곳

| 하고 싶은 일 | 볼 곳 |
| --- | --- |
| 기록에 필드 추가 | `lib/types.ts` → `lib/status.ts`(`newExpense`, 필수라면 `missingFields`) → `lib/agent.ts`(`RECORD_FIELDS`와 `update_record` 도구) → `lib/flow.ts`(`AGENT_FIELDS`) → `lib/ledger.ts`(`recordBody`) → 화면 |
| 에이전트에 도구 추가 | `lib/agent.ts`의 도구 목록. 상태를 바꾸는 도구는 넣지 않습니다 |
| 에이전트의 말투나 판단 기준 | `lib/agent.ts`의 `EXPENSE_SYSTEM`, `CLOSE_SYSTEM` |
| 다른 모델 제공자로 바꾸기 | `lib/liner.ts`의 `chatWithTools`, `searchWeb` 두 함수 |
| 다른 저장소로 바꾸기 | `lib/sync-store.ts`의 `SyncStore` 인터페이스를 구현 |
| 결산보고서 항목 | `lib/report.ts`(자료와 HTML), `app/report-view.tsx`(화면) |
| 화면 문구와 배치 | `app/app/page.tsx`. Astryx 부품을 씁니다([CONTRIBUTING.md](../CONTRIBUTING.md)) |

## 화면이 깨졌을 때

화면을 그리다 오류가 나면 `app/error.tsx`(틀까지 깨지면 `app/global-error.tsx`)가 흰 화면 대신 오류 화면(`app/error-screen.tsx`)을 보여 줍니다. 기록이 기기에 그대로 있다고 알리고, 앱이 열리지 않아도 `lib/rescue.ts`로 기록을 백업 파일로 꺼낼 수 있게 합니다. 없는 주소는 `app/not-found.tsx`가 받습니다. `/debug/error`는 일부러 오류를 내 보는 시험 페이지입니다.

오류 화면은 잡은 오류를 `lib/error-hook.ts`의 `reportError`로 넘깁니다. 오류 수집 도구를 붙였다면 거기로 가고, 붙이지 않았다면 아무 데도 보내지 않습니다. 밖으로 보내는 글은 `lib/scrub.ts`를 거쳐 열쇠(주소의 # 뒤), 번호, 사진, 화면에 적은 글을 지웁니다.

## 알려진 한계

- 로그인이 없습니다. 승인 규칙과 역할은 화면 수준의 약속이고, 단체 공간에 참여한 사람(초대 링크, 잠근 공간이면 암호까지 아는 사람)은 모든 기록을 읽고 고칠 수 있습니다. 구성원을 내보내거나 암호를 바꾸는 기능은 없어, 그럴 때는 공간을 새로 만듭니다.
- 호출 제한은 서버 인스턴스의 메모리에 있어 정확한 상한이 아닙니다.
- `app/app/page.tsx`가 한 파일에 1,400줄입니다. 화면별로 나누는 것이 다음 정리 대상입니다.
- 영수증 사진의 해시는 원장에 남지만, 사진이 바뀌었는지 보여 주는 화면은 없습니다.
